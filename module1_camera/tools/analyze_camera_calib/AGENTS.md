# AGENTS.md — analyze_camera_calib 相机标定分析工具

> 单文件 Node 脚本：对 camera_calib.exe 的产物 JSON 做质量体检、离群帧归因、跨批次对比与共性问题判定。零依赖、不进 CMake、不改动标定流程本身。

## 一句话用法

```powershell
node analyze_camera_calib.mjs <camera_calib.json ...> [--out 目录] [--reproj-th px] [--epipolar-th px] [--no-charts]
```

示例（两批对比，几何归因需 config 旁置）：

```powershell
# 每份 JSON 放独立目录（目录名＝报告里的 label），同目录放棋盘 config.json
node analyze_camera_calib.mjs data1\camera_calib.json data2\camera_calib.json
```

## 输入要求

| 输入 | 要求 | 缺失后果 |
|---|---|---|
| camera_calib.json | 模块1 产物（schema `factory_calib.camera_calib.v1`），1..N 份 | 坏文件自动跳过；全失败 exit 2 |
| 棋盘 config.json（可选） | 放 JSON **同目录或上级**，需 `chessboard.width/height`＋`square_size_mm` | 距离/斜角/覆盖审计等标 N/A，指纹 R2/R3/R8 判"证据不足" |

- 阈值优先级：`--reproj-th` > 旁置 config 的 `reproj_error_threshold` > 默认（reproj 0.012 / epipolar 0.05）
- 退出码：0 正常；2 参数错/输入全失败；1 报告与 summary 双写失败（终端表始终先打印，不会白跑）

## 输出（默认落脚本旁 `out/camera_calib_<时间戳>/`，`--out` 可改）

| 文件 | 内容 |
|---|---|
| `report.md` | 人类可读主报告：开头有「指标说明」词汇表（9 组通俗解释），后接每份体检九节＋跨批次对比三节 |
| `summary.json` | 全部指标机器可读（供趋势工具/脚本消费） |
| `charts/*.svg` | 每批误差条形图（双阈值线）/直方图/误差-几何散点/姿态覆盖图＋跨批对比图 |

## 分析模型（两层）

**第一层·多维统计（五域）**
- A 标定可信度：覆盖审计（帧≥10 / 姿态≥2 方向 / 画面角落覆盖）＋0.1px 参考量级＋跨批投影差异场
- B 双目一致性：L−R 失衡波动、corrLR、内外参解耦度、β 距离斜率（含去杠杆稳健值）
- C 采集数据质量：误差×距离/斜角/覆盖相关（带显著性与偏相关）、离群帧深挖、畸变参数
- D 物理检查：覆盖审计不过时报告自动附人工核查清单（板平整/对焦/光照）

**第二层·指纹规则库（8 条）**

| 规则 | 问题 |
|---|---|
| R1 | 双目对焦/距离响应不一致 |
| R2 | 姿态覆盖不足 |
| R3 | 远距小板亚像素不足 |
| R4 | 外参/装配嫌疑 |
| R5 | 单相机劣化 |
| R6 | 全局场景问题（光照/棋盘） |
| R7 | 采集期热漂 |
| R8 | 数据量/姿态病态 |

判定：⚠命中 / —排除 / ? 证据不足。**同一指纹多批命中＝共性问题**：2-3 批「线索级」，≥4 批「结论级」（summary 可支撑滚动重评）。

## 必读注意事项

1. `view#` 是跳帧后重排的序号，≠原始图片文件编号
2. GBK 控制台中文乱码只是显示问题，文件本体 UTF-8 正常——报告用编辑器看
3. JSON 里 `total_frames_input`＝有效帧数，原始跳帧数只在标定日志里
4. 工具只测「数据质量＋模型一致性」，测不了标定真不确定度（需重标定交叉验证）与板平整度（物理项）
5. 指纹阈值是一期经验值（实证 4 单元），随批次积累可再标定
